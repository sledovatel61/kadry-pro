# Прослойка заявок kadry-pro.ru

Шлюз между статическим сайтом на GitHub Pages и Telegram-группой Марии плюс
почтой: заменяет американский Formspree. Код — Cloudflare Worker в этой папке.

## Что умеет

| Адрес | Метод | Что делает |
| --- | --- | --- |
| `/health` | GET | Живой ли воркер, видит ли Telegram и почту, принимает ли отзывы |
| `/leads` | POST | Заявка с любой формы `[data-lead-form]`: консультация, калькулятор, заказ шаблона, запрос шаблона за email |
| `/files/:token` | GET | Разовая подписанная ссылка на скачивание шаблона (email-пакет и пакет 25 шаблонов) |
| `/reviews` | GET | Опубликованные отзывы клиентов (без модерации, сразу с сайта) |
| `/reviews` | POST | Приём отзыва: публикуется сразу, уведомление уходит в Telegram и на почту |
| `/reviews/inbox` | GET | Все отзывы, включая скрытые (вход — ключ GitHub из `/manage/`) |
| `/reviews/moderate` | POST | Скрыть / вернуть / удалить отзыв (тот же ключ) |

Правила, которые воркер соблюдает всегда:

- **antispam**: honeypot, «слишком быстрое» заполнение (меньше 4 секунд), лимит
  5 заявок за 10 минут с одного адреса (IP хранится только как обрезанный хэш),
  строгая проверка полей и запрет ссылок в отзывах;
- **контракт ошибок**: `{error:{code,message,fields}}` для заявок,
  `{error:'code'}` для отзывов — клиентские скрипты разбирают оба вида;
- **два канала доставки**: заявка считается принятой, если сработал хотя бы один
  канал (Telegram или почта). Оба подвели — 502 и просьба позвонить;
- **приватность**: в логах только талон, длина текста и результат доставки.

## Настройка (владельцу, 10 минут)

1. Создать бота в Telegram у [@BotFather](https://t.me/BotFather) — команда
   `/newbot`, получить токен вида `123456789:AA...`.
2. Добавить бота в **группу заявок** (или в личный чат с Марией) и дать право
   писать. Узнать `TELEGRAM_CHAT_ID` группы: id — отрицательное число, вида
   `-1001234567890`. Проще всего: написать в группу любое сообщение, открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `chat.id`.
3. В GitHub → Settings → Secrets and variables → Actions добавить секреты:
   - `CLOUDFLARE_API_TOKEN` — токен Cloudflare с шаблоном «Edit Cloudflare Workers»;
   - `CLOUDFLARE_ACCOUNT_ID` — необязателен: workflow определит его по токену;
   - `BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — id группы (отрицательное число);
   - `BREVO_API_KEY` **или** `RESEND_API_KEY` — для копии письма
     (без ключа заявки идут только в Telegram, сайт это переживёт);
   - `EMAIL_TO` — `m.perepechay@yandex.ru`;
   - `EMAIL_FROM` — необязателен, но для Resend нужен подтверждённый домен.
4. Запустить workflow **Deploy leads relay** (Actions → выбрать → Run workflow).
   В Summary появится адрес воркера вида `https://kadry-leads.<сабдомен>.workers.dev`.
5. Этот адрес положить в GitHub → Settings → Variables → `PUBLIC_LEADS_ENDPOINT`
   (без слэша в конце). Если переменной нет, сайт работает как раньше: формы
   показывают телефон и не отправляют данные никуда.
6. Проверка: открыть `https://<адрес>/health` — должно быть
   `"telegram":true`, `"reviews":true`. Потом отправить тестовую заявку с сайта.

Секретов в репозитории нет и быть не должно: всё через секреты GitHub и
`wrangler secret put`.

## Локальная разработка

```bash
cd relay
npm install
npm test            # юнит-тесты, сеть подменена — наружу ничего не уходит
npm run typecheck
npx wrangler dev --var ALLOWED_ORIGINS=http://localhost:4321
```

Секреты для локального запуска кладутся в `relay/.dev.vars` (в git не попадает).

## Защищённая выдача шаблонов

Платные и email-шаблоны не лежат в открытой статике. Заявка на шаблон уходит в
Telegram, а воркер возвращает ссылку `/files/<подписанный токен>` — она живёт
24 часа и подписана секретом `FILE_TOKEN_SECRET` (если секрета нет, используется
соль из `BOT_TOKEN`). Файлы хранятся в приватном бакете, привязанном к воркеру
(binding `TEMPLATES`); пока бакета нет, `/files` честно отвечает 404 —
ссылок на несуществующие файлы воркер не раздаёт.
