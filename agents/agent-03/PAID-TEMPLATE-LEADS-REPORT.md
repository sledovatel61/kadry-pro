# Отчёт (Раунд 9): заявка на конкретный платный шаблон с ручной отправкой Марией

- **Ветка:** `arena/4a8011ca-kadry-pro` (активная рабочая ветка сессии; в `main` не пушили, оплату, R2, секреты и DNS не трогали).
- **Фиксированный коммит с PDF-файлами для ссылок Марии:** `ac75af6c9352be4c874cc84650e0401c59216e7c` (`origin/main` до удаления платных PDF из корня сайта).

## 1. Что сделано

### На сайте (`site/`)
1. **Кнопка заявки у каждой из 44 платных карточек (`site/src/pages/shablony.astro`)**
   - Вместо увода на общую страницу `/contact.html?service=templates` у всех 44 платных карточек (`price: 500`, `free: false`) добавлена кнопка **«Оставить заявку»** (`data-open-template`, `data-template-id`, `data-template-title`, `data-template-price="500"`, `data-template-package="single"`), а каждой карточке проставлен якорь `id="s01"`…`id="s64"` в соответствии с `ItemList` JSON-LD.
   - В блоке внизу каталога сохранена ссылка «Задать вопрос» и добавлена кнопка заказа всего набора (`Весь набор · 3 500 ₽`, `package="full"`, цена синхронизирована с `site/content/prices.json` → `templates.bundle-64`).
   - Все **20 бесплатных шаблонов** (`/shablony/free/*.pdf` и старые корневые пути бесплатных файлов) и архив `/shablony/free-bundle-20.zip` полностью сохранены без изменений.

2. **Модальное окно заявки на выбранный шаблон (`site/src/pages/shablony.astro` + `site/src/client/template-modal.ts`)**
   - Нативный `<dialog id="template-lead-modal">` показывает номер, название и цену выбранного документа и честно предупреждает покупателя: оплата на сайте пока не проводится, Мария получит заявку, свяжется, согласует оплату и отправит документ вручную.
   - Подключён к общему клиенту `site/src/client/leads-form.ts` (`data-lead-form`, `data-lead-kind="template"`): сохранены честные статусы доставки по `delivered.telegram` / `delivered.email`, ротация `idempotency_key` на `409`, защита от потери заявки при автозаполнении офскрин-ловушки (`K-1123`) и повторное открытие формы при выборе следующей карточки без перезагрузки страницы.
   - **Мобильная форма и автозаполнение (`site/src/client/leads-form.ts`, `site/src/client/site.ts`):**
     - размер шрифта `16px` на всех полях ввода модалки (защита от принудительного автозума iOS Safari);
     - корректные `autocomplete="name"`, `autocomplete="tel"`, `inputmode="tel"`, `autocomplete="email"`, `inputmode="email"`;
     - исправлена обрезка последней цифры номера на телефонах при вставке/автозаполнении полного номера (`+7…` или `8…`) поверх подставленного при фокусе префикса `+7` / `+7 (` (`formatPhoneMaskValue` + слушатель `change`);
     - чтение выбранного способа связи (`Telegram` / `WhatsApp` / `MAX` / `Звонок`) из поля `[name="contact_method"]`;
     - кнопка «Заявка» в нижней мобильной плашке (`[data-dock-lead]`) пропускает форму внутри закрытого `<dialog>`.

### На сервере приёма заявок (`relay/`)
1. **Проверенный серверный каталог (`relay/src/paid-templates.ts`)**
   - Содержит точное сопоставление всех **44 платных ID** (`"02"`…`"62"`) с названием, серверной ценой (`500 ₽`) и именем PDF-файла в коммите `ac75af6c9352be4c874cc84650e0401c59216e7c`.
   - Цена, название и ссылка формируются **только на сервере**: подменённая цена, поддельное название или произвольный `url` из браузера игнорируются.
   - Формат ссылки (только для Марии):
     `https://raw.githubusercontent.com/sledovatel61/kadry-pro/ac75af6c9352be4c874cc84650e0401c59216e7c/shablony/<encodeURIComponent(filename)>`
     Поскольку ссылка привязана к полному 40-символьному SHA коммита `ac75af6...`, удаление `shablony/*.pdf` из текущей ветки `main` при выпуске сайта не сломает скачивание для Марии.
   - Для **неизвестного ID** (а также если передан ID бесплатного шаблона, например `"01"`) ссылка **не формируется**, а цена из браузера **не подтверждается** — но сама заявка покупателя всё равно доставляется Марии с явной пометкой.
   - В HTTP-ответе `POST /leads` клиенту ссылка **никогда не возвращается** (`download === undefined`, в JSON нет упоминаний GitHub или `.pdf`).

2. **Уведомления Марии в Telegram и на почту (`relay/src/telegram.ts`, `relay/src/email.ts`, `relay/src/validate.ts`)**
   - В `validate.ts` разрешены двузначные каталожные ID `"01"`…`"64"` (с сохранением совместимости со старым форматом `tNN`) и передача необязательного комментария `message` для `kind: 'template'`.
   - В Telegram (`HTML`) и в письме (`text` и `html`, с кликабельной кнопкой `Скачать PDF` в HTML-письме и чистым ASCII URL в текстовой версии) Марии приходят:
     1. проверенное название и `ID` выбранного шаблона;
     2. цена, указанная покупателю на сайте, сверенная с серверным каталогом (`500 ₽` для одиночного платного шаблона, `3 500 ₽` для полного набора);
     3. имя, телефон, выбранный способ связи, почта/комментарий (если указаны) и номер заявки (`ticket`);
     4. прямая ссылка на файл в GitHub (только для подтверждённых 44 платных одиночных ID);
     5. явная пометка: *«Ссылка только для удобства Марии — ведёт на публичный GitHub (коммит ac75af6, не защищённая выдача и не секрет; покупателю не показывается)»*.

1. **Проверка всех 44 платных одиночных PDF (`"02"`…`"62"`):**
   - Сверена 100%-ная синхронизация `site/content/templates.json`, `site/content/prices.json` (`templates.single = 500`) и `relay/src/paid-templates.ts`.
   - В коммите `ac75af6c9352be4c874cc84650e0401c59216e7c` проверено наличие всех 44 файлов в `shablony/`, валидность заголовка `%PDF-1.4` у каждого файла и совпадение внутреннего PDF-поля `/Title` с темой карточки каталога (все 44 документа соответствуют своим названиям и префиксам `ID_`).
   - Проверено RFC-3986 кодирование русских имён (включая букву `ё` в ID `53`, `55`, `60` и дефис в ID `28`): все 44 адреса состоят только из безопасных ASCII-символов и проверены живыми `HEAD`-запросами к `https://github.com/sledovatel61/kadry-pro/raw/ac75af6c9352be4c874cc84650e0401c59216e7c/shablony/<encoded>` — **44 из 44** отдают `HTTP 302` на ожидаемый `raw.githubusercontent.com` URL без единого `404`.

2. **Проверка архива для «Полного набора из 64 шаблонов» (`package: 'full'`, `3 500 ₽`):**
   - Проверены все архивы в истории репозитория (`ba0e432` и `ac75af6`):
     - `shablony/free-bundle-20.zip` — содержит **только 20 бесплатных PDF**;
     - `shablony/email-bundle.zip` — содержит **только 25 PDF** (подборка «за подписку», причём внутри ZIP имена в кодировке CP866), а **не 64 документа**;
     - отдельного архива или сводного PDF на все **64 документа** в git **не существует**.
   - В соответствии с правилами задачи: ни один из существующих архивов **не назван полным пакетом**, ссылка для `package: 'full'` **не выдумывается и не формируется**. При заявке на полный набор сервер проставляет каталожную цену `3 500 ₽` и пишет в уведомлении Марии: *«Подтверждённого архива полного пакета (64 документа) в GitHub нет — ссылка не формируется, отправьте комплект вручную»*.

## 4. Нужно ли обновлять Cloudflare Worker через GitHub Actions после слияния?

**Да, воркер `kadry-leads` нужно обновить**, так как серверная сверка каталога из 44 платных шаблонов (`relay/src/paid-templates.ts`), приём двузначных каталожных ID (`"02"`…`"62"`) в `relay/src/validate.ts` и формирование ссылок в `relay/src/telegram.ts` / `relay/src/email.ts` живут именно в воркере (текущий продовый воркер до деплоя принимает `template.id` только вида `t\d+` и не добавляет ссылку из GitHub).

**Как это произойдёт:**
- Workflow `.github/workflows/relay.yml` (`Deploy leads relay`) уже настроен на автоматический запуск при пуше/слиянии в `main`, затрагивающем `relay/**`:
  ```yaml
  on:
    push:
      branches: [main]
      paths:
        - 'relay/**'
        - '.github/workflows/relay.yml'
    workflow_dispatch:
  ```
- Поэтому **сразу после слияния ветки в `main` GitHub Actions автоматически соберёт, прогонит тесты и задеплоит обновлённый воркер `kadry-leads`** (никакие секреты, R2 или DNS менять не требуется). После слияния достаточно убедиться во вкладке **Actions → Deploy leads relay**, что автозапуск завершился зелёной галочкой (либо при необходимости нажать **Run workflow** вручную).
